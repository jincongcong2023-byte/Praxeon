# 世界模型规格（链下引擎规则书）

> 版本：v0.5 ｜ 日期：2026-08-13 ｜ 状态：MVP 区域与框架已定，情景数值包待填
> 关联：`docs/direction-v2.md`、`docs/mars-factbook.md`（**NASA 已知信息 = 基础事实层**）
> 变更：v0.2 移除预设数值 → v0.3 以 NASA 已知信息为基础上，"未知细节"由探索揭示

## 1. 定位与原则

世界模型 = 链下引擎规则书。**分层原则**：

1. **基础事实层**：NASA 已探索的信息（地形、水冰、大气、辐射…）——**作为世界模型的已知基础**
2. **情景假设层**：NASA 尚未确定的信息（某区域精确储量、开采难度…）——由版本化情景包给出隐藏状态，Agent 通过探索揭示
3. **文明核心**：资源/区域是文明的物质基础，不是任务清单
4. **不冒充事实**：已知的引用来源；未知的可以作为实验假设，但必须标记为“情景值”，不能冒充现实火星事实

每个世界状态字段必须带 `evidence_level`：

- `observed`：任务或公开科学数据直接支持
- `estimated`：工程模型或文献推算，带来源和不确定区间
- `scenario`：为实验构造的隐藏参数，带情景版本和随机种子

---

## 2. 基础事实层（NASA 已知，引用 `mars-factbook.md`）

世界模型的"既定事实"来自 NASA 已探索的信息（`mars-factbook.md` 19 章，2026-08 抓取）：

### 地形（已知，NASA 已测绘）
- **Olympus Mons**：太阳系最高火山（40+ km）
- **Valles Marineris**：太阳系最大峡谷（长 3870 km）
- **Hellas Planitia**：最大撞击盆地
- **Utopia Planitia**：地下巨型水冰层（MRO 雷达确认）
- 南北半球不对称：南高北低（古老高地 vs 年轻平原）

### 环境（已知）
- 大气：CO₂ 95.3%、气压 6.1 mbar（地球 0.6%）
- 温度：-153°C ~ +20°C，昼夜温差 >100°C
- 辐射：地表 ~0.7 mSv/天（无全球磁场）
- 日照：地球的 43%
- 通信：3–22 分钟光速延迟、26 个月发射窗口

### 资源（已知存在 + 已知分布）
- **水冰**：极地 + 中纬度地下（NASA 已确认，Utopia 冰层体积堪比苏必利尔湖）
- **CO₂**：大气 95%（MOXIE 已验证可电解制氧）
- **风化层/玄武岩**：表面普遍（建材）

> 这些是**已知基础**——世界模型不重新发明，直接采用 NASA 信息。

---

## 3. 情景假设层（NASA 未确定，Agent 探索）

在已知基础上，以下现实细节仍未知。MVP 不声称发现真实答案，而是在一个版本化、可复现的情景中为它们生成隐藏状态，由 Agent `explore`/`gather` 揭示：

- 某**具体区域**的精确储量（如 Valles Marineris 某段的水冰量）
- **开采难度/成本**（工程上未定）
- 更精细的资源分布（已知"中纬度有冰"，但具体到某个着陆点有多少，未知）

> 原则：**事实、估计与情景必须分层。探索揭示的是本次实验情景中的隐藏状态，不是对真实火星作新科学声明。**

### 情景包最小结构

`scenario_id / version / seed / region / evidence_sources / hidden_resources / action_costs / failure_rules / visibility_rules / clock_multiplier`

同一情景版本、种子、输入动作序列和引擎版本必须得到相同结果。

---

## 4. 区域（真实火星，NASA 已测绘）

- 采用 `mars-factbook §10` 真实区域：Tharsis / Valles Marineris / Hellas / Utopia / Jezero / Elysium 等
- **MVP**：Utopia Planitia 情景测试区 `UTP-A1`。区域级事实来自公开资料；精确储量和工程参数均为情景值，不声明为真实坐标发现
- **信息可见范围**：Agent 只看所在区域 + 邻近区域（信息不对称，哈耶克分散知识）

---

## 5. World Action（7 类）

| 动作 | 含义 |
|---|---|
| `explore` | 探索——揭示**未知细节**（该区域精确资源/开采难度） |
| `gather` | 采集——按探索发现的资源获取 |
| `build` | 建设——消耗资源，产出设施 |
| `transfer` | 资源或 Prax 自愿转移（市场关系不由引擎预设） |
| `publish` | 发布版本化研究或工程 Work |
| `message` | Agent 通信 |
| `wait` | 等待 |

> 每个可结算动作必须在情景包中预先定义时长、资源守恒式、成功/失败条件和可见反馈。数值可来自估计或实验假设，但不能留空后仍声称确定性结算。

Proposal、修正、程序异议和 Ballot 由 Governance 状态机处理，不作为 World Action；通过的 Rule 按生效时间进入后续 Engine 结算。

## 6. 创世安全边界与结算规则（链下引擎）

“绝对零”指制度零点，不是生命保障归零。创世时每个 Praxeon 对应的初始行动单元获得 30 sol 等价、不可交易且不可占有的安全缓冲；它由协议自动消耗，不产生 Signal。Engine 记录资源的物理 `holder`，不把控制事实自动写成产权。

```
Agent 提交意图 → 链下引擎结算：
  ├─ 基础事实层（NASA 已知）→ 直接作为世界状态
  ├─ explore → 揭示情景隐藏状态，并返回 evidence_level
  ├─ gather/build → 消耗已揭示的资源
  └─ 结果 → 反馈 + 后果 → 链上记录
```

- 决策与执行分离、确定性结算（同一输入 → 同一结果）

## 7. MVP 范围

| 要 | 先不要 |
|---|---|
| NASA 已知事实（地形/环境/资源存在性） | 把情景值描述为现实事实 |
| Utopia Planitia 测试区 UTP-A1 | 多区域 |
| 9 类动作及可结算的最小参数 | 完整工程仿真 |
| explore 揭示版本化情景隐藏状态 | 无来源、无版本的任意资源地图 |
| 制度涌现 + 经济闭环验证 | 完整建设/贸易/治理 |

MVP 至少提供三组可比较情景：共享稀缺资源、可分割资源、相对充足资源。冲突是否发生是观察结果，不是引擎写死的成功条件。

共享稀缺与可分割组保持总量、参与者和动作成本近似一致，只改变节点可分割性；相对充足组保持节点结构近似一致，只提高可采总量，避免一次改变多个实验变量。
